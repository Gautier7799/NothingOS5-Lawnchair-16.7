6. SECURITY REVIEW
--------------------------------------------------------------------------------

Full threat model (13 threats, each mapped to a control) and an operator
checklist are in docs/SECURITY.md.

READ-ONLY BY CONSTRUCTION
  The only HTTP verb in client.py is GET. There is no code path that can send a
  message, execute a command, modify a file or create a conversation. A test
  asserts that every request recorded by the fake upstream uses GET.

FAIL-CLOSED AUTHENTICATION
  The server refuses to start when no auth mode is configured
  (MCP_REQUIRE_AUTH=true by default). Verified: starting with no token and no
  OAuth issuer prints
  "Refusing to start an unauthenticated remote MCP endpoint."

ENDPOINT AUTHENTICATION
  - Static bearer tokens: 256-bit values from secrets.token_urlsafe(32); only
    the SHA-256 hash is retained after startup; compared with
    hmac.compare_digest (constant time).
  - OAuth 2.1 / OIDC (optional): JWTs verified against the issuer's JWKS
    (signature, "iss", optional "aud"); RFC 9728 and RFC 8414 discovery
    documents are published so ChatGPT can run the auth-code + PKCE flow.

SECRET HANDLING
  - OPENHANDS_CLOUD_API_KEY is read once at startup and held in memory.
  - Config.__repr__ prints "<redacted:N chars>" instead of the value.
  - Every tool result and error body passes through recursive redact(), which
    replaces any key matching *api_key, *_secret, *_token, authorization,
    password, provider_tokens, session_api_key, and scrubs sk-..., sess-...,
    "Bearer ..." and JWT-shaped strings inside free text.
  - The configured key is additionally passed as an extra literal to scrub.

DATA MINIMISATION
  session_api_key and conversation_url (both grant direct sandbox access) are
  stripped from conversation summaries.

INPUT VALIDATION
  conversation_id is restricted to [A-Za-z0-9_-]{1,64} and URL-quoted before it
  is placed in a path. All numeric bounds are enforced by pydantic. Invalid
  input returns code "invalid_input", never a 500.

ERROR HYGIENE
  Upstream error bodies are truncated to 400 bytes and redacted. Unexpected
  exceptions are logged server-side and returned to the model as a generic
  "upstream_error" payload, so FastMCP cannot stringify an internal exception
  into tool output.

RATE LIMITING AND RESOURCE CAPS
  Per-principal token bucket (default 60 requests/min) plus a separate upstream
  limiter. Hard caps on page size, single event size, response size, event count
  and trajectory archive size (128 MiB, streamed and abandoned past the cap).

TRANSPORT AND CONTAINER HARDENING
  Container runs as non-root (uid 10001) with all capabilities dropped,
  no-new-privileges and a read-only root filesystem. The provided Caddy/nginx
  configs set HSTS, X-Content-Type-Options: nosniff, Referrer-Policy:
  no-referrer, hide server tokens and cap request bodies at 1 MB.

REPOSITORY HYGIENE
  .gitignore excludes .env, .env.*, secrets/, *.pem, *.key, dist/, caches.
  Only .env.example is committed. The pushed branch tree was scanned:
  0 secret hits across 39 files.

BUGS FOUND BY LIVE TESTING, NOW FIXED (with regression tests)
  1. OpenHands Cloud returns "[null]" with HTTP 200 for an unknown conversation
     id, which previously crashed as
     "AttributeError: 'NoneType' object has no attribute 'get'".
     Now mapped to code "not_found".
  2. Unexpected exceptions were being stringified into tool output by FastMCP.
     Now caught in server.py::_dispatch, logged server-side, and returned as a
     generic "upstream_error".

REMAINING ISSUES / LIMITATIONS (all also in docs/SECURITY.md)
  1. Single-tenant. The bridge holds one OpenHands API key; anyone who can
     authenticate can read every conversation that key can see. Issue one bridge
     per trust boundary.
  2. In-process rate limiting. Counters are per process; for multiple replicas,
     add a limiter at the ingress.
  3. Redaction targets credentials, not confidential content. Treat
     conversation content as data you accept placing in a model context.
  4. Static tokens do not expire. Rotate MCP_AUTH_TOKEN on a schedule, or use
     OAuth mode for revocation.
  5. No per-caller audit log of which conversation was read.
  6. Trajectory archives are large; the download itself still transits the
     bridge even though the returned payload is capped.
  7. Benign teardown message. On interpreter shutdown, sse_starlette may print
     "Task was destroyed but it is pending". Cosmetic; no test failure and no
     effect on requests.
  8. The public sandbox endpoint is ephemeral and will stop when the sandbox is
     reclaimed.

10. CONNECTING THE MCP SERVER TO CHATGPT
--------------------------------------------------------------------------------

Full walkthrough: docs/CHATGPT_CONNECTOR.md

  1. Confirm the server is up:
       curl -s https://<your-host>/healthz
     Expected: {"status":"ok",...}

  2. Generate an MCP token (this is NOT the OpenHands API key):
       python -c "import secrets; print(secrets.token_urlsafe(32))"
     Store it privately: environment variable MCP_AUTH_TOKEN, or a 0600 file
     referenced by MCP_AUTH_TOKEN_FILE.

  3. In ChatGPT: Settings -> Connectors -> Add custom connector
     (enable Developer mode if your account requires it).

  4. URL: https://<your-host>/mcp
     Include the exact "/mcp" path.

  5. Authentication: API key / Bearer token.
     Paste your MCP_AUTH_TOKEN.
     Never paste the OpenHands Cloud API key -- ChatGPT never needs it and
     never sees it.

  6. Save. ChatGPT should list the five openhands_* tools.

  7. Try a prompt:
       "List my five most recent OpenHands Cloud conversations."
       "Show the status of conversation 7177c0cd42934b7db0ec620706f3f547."

CONFIGURING OPENHANDS_CLOUD_API_KEY AS A PRIVATE SECRET
Never put it in source code, chat, or version control.

  Local:
      cp .env.example .env && chmod 600 .env
      set -a; . ./.env; set +a

  Docker:
      Write the key to secrets/openhands_cloud_api_key with mode 0600.
      docker-compose.yml mounts it at /run/secrets/... and the app reads it via
      OPENHANDS_CLOUD_API_KEY_FILE, so it never appears in "docker inspect" or
      in the image layers.

  Kubernetes:
      kubectl create secret generic openhands-mcp \
        --from-literal=OPENHANDS_CLOUD_API_KEY=...
      Then reference it with envFrom.secretRef in deploy/k8s.yaml.

  Cloud secret manager:
      AWS Secrets Manager / GCP Secret Manager / Azure Key Vault / HashiCorp
      Vault, injected at runtime as an environment variable or file.

For OAuth instead of a static token, set MCP_OAUTH_ISSUER (and optionally
MCP_OAUTH_AUDIENCE). The bridge publishes the discovery documents ChatGPT
needs, and no static token is required.
